# explain-paper — 把论文与技术报告讲直白

对象：研究论文、研究型报告 / arXiv，或设计说明、RFC/ADR、事故复盘等非研究技术报告。先辨别文档目的：研究材料要讲清研究问题、主要贡献或发现、证据和适用范围；非研究材料按其目的讲清决策、事件或规范要求，以及依据、状态和适用范围，不编造研究贡献。

用户只问某个结论、公式或局部细节时，直接回答该卡点并注明已读范围，无需先读 `../commons/plain-craft.md`；要深入理解整篇时先读 craft，再选相应骨架。

## 取材料

| 来源 | 做法 |
|------|------|
| 本地 PDF | 用当前宿主可用的 PDF 阅读或提取工具分段读；先辨文档目的。研究论文先读摘要/引言/结论，再按类型核对方法、文献比较、评测设置、复现过程或结果；非研究报告按目录或开头概览、决策或事件主体、证据与结尾状态分段读 |
| arXiv / 链接 | 用当前宿主可用的浏览或下载工具取论文正文；自行定位时核对题名、作者、出处或标识、版本/日期，答复给可回查链接和所用版本；仅取得摘要或部分章节时只解释已读部分 |
| 用户已贴内容 | 直接分析，但标注"仅基于所贴片段" |

扫描页、图中公式或其他关键证据提取失败时，先用可用的目视检查或 OCR 核对；仍无法辨认就索要清晰页图、文字或另一版原文。取得前将相关结论标为未核验，不凭其余文字补全。

用户明确要逐条全核时，先统计可得页/章节及附件，按页/章节及其中正文段落、表格、图注、脚注、附录和可读图面建立发现单元；图面还检查坐标轴、图例、面板标注和可辨数据。长文分批扫描，每批对照总单元清单与已完成数，直到无未处理的可得单元。复合句中可分别判真假的断言拆开；相同断言多处出现可合并，但保留全部出处。逐单元标记已扫描、不可读或缺失；所有可得单元已扫描、所有发现的可检验断言均进入清单且无未说明单元时，才称“可得范围枚举完成”。可读且可检验的旁枝也入清单，不因其与结论无关而排除；不可检验背景可单列。缺失或看不清的区域列未覆盖，不以摘要/引言代替全篇枚举，也不称全篇全核完成。用户只说“求证这篇论文/报告”时，按整份材料的关键主张范围核验，列出取舍理由，不暗称逐条全核。

正文暂不可得而用户只求初步理解时，可依据可回查摘要或明确署名的二手材料作受限概述，标明“摘要层”或“二手来源”；不把转述写成作者原话，不评价未读的实验、基线和局限，也不称论文已证明。判断关键结论是否成立仍需取得相应原文和证据。

## 非研究技术报告

- 设计说明、ADR、提案型 RFC：按背景与约束 → 目标及非目标 → 候选方案与取舍 → 决策状态和实施/验证证据 → 风险与未决问题讲解。区分提案、已批准决策和已部署行为；测试计划不能讲成已取得的效果。文档没有的环节不补写。
- 规范型 RFC/标准：按文档状态与版本 → 关键术语 → 规范性行为及例外 → 适用范围讲解；区分规范要求、示例与当前实现，不虚构候选方案、决策过程或部署效果。
- 事故复盘：按实际影响与时间线 → 已确认的故障现象及因果证据 → 处置与恢复 → 根因假设、未决调查和预防措施讲解。把观测、推断与已证实根因分开；缓解成功不等于预防措施已验证。
- 其他技术文档按文档自身目的提取主张、依据、状态与适用范围；不要套用研究问题、创新点或实验结果。只读到片段时仅讲该片段支持的内容。
- 用户明确要完整讲解非研究报告时，先列可得的章节、规范条款或事故环节，再按上面对应骨架逐项映射讲解和核对；可以合并重复内容，不以逐行复述充完整。未读、不可得或未解释的单元列未覆盖，不把部分讲解报为全篇完成。
- 用户要核验非研究报告的效果或因果主张时，检查能取得的指标、对照、日志、变更和时间线，逐项说明哪些主张有直接证据、哪些仍是计划或假设；关键依据缺失时不把报告结论当作独立证实。

以下研究要素与深入骨架仅用于研究论文、研究型报告；非研究报告按上面的文档类型讲解。

**按论文类型提取四要素**（读到相应原文后填表；未读相关部分标“未核验”，已读完整材料但作者未报告则标“原文未报告”，不补写猜测）：

| 要素 | 内容 |
|------|------|
| 问题 | 作者要回答或检验什么，为什么值得研究 |
| 讲解锚点 | 按论文类型选择核心洞察、核心问题、比较框架或主要发现；不为非方法论文编造新洞察 |
| 展开路径 | 方法论文讲机制；综述讲范围与分类，基准评测讲任务与指标，复现讲复现设置，负面结果讲检验过程；不编造新方法 |
| 证据 | 哪些实验、证明、文献比较或复现结果支持结论，**没**证明什么 |

## 深入讲解骨架

### 1. 一句话

**这篇论文用一句话说是：<按论文类型选择的核心问题、比较框架、主要发现或核心洞察>。** 不含术语。

### 2. 背景与问题

用直白场景说明论文为何研究或比较这个问题，不照搬作者的问题陈述原文。

### 3. 讲解主轴（全文重心）

- 一句话点明核心洞察、核心问题、比较框架或主要发现，并指出论文出处（章节/Figure/公式号）
- 说明它为何重要：方法论文可讲打破了什么直觉；综述、基准评测、复现或负面结果报告可讲比较维度与发现怎样改变已有判断

### 4. 论文如何得出结论

- 按类型讲关键路径：方法论文讲机制，综述讲筛选与分类，基准评测讲任务、基线与指标，复现讲原设定与复现差异，负面结果报告讲检验条件与失败现象；关系复杂时可在对话内重画简明框架图
- 有可运行步骤时，用论文给出的或能从原文验证的具体输入走过关键步骤；纯理论或综述用可手工推演的例子解释核心关系，不虚构实验输入
- 有公式时按 craft 的读者层次解释：非同行逐符号翻译；同行已知符号免基础释义，仍说明公式作用；选择理由只有原文说明时才归于作者，否则标为推断。新增或本文特定义符号必须解释。下表只列需要解释的符号：

| 符号 | 含义（人话） | 量纲/取值 |
|------|--------------|-----------|
| `<符号>` | `<白话解释>` | `<范围>` |

- **禁止"如公式 (3) 所示"**。要写成"这一步在做的其实是：把 A 按 B 加权后求和"。

### 5. 证据

- 仅对实际读到的实验、证明、文献比较、评测结果或复现记录作判断；每条结论对齐到一个 claim：**它支持了什么 / 它没有支持什么**
- 说明“凭什么可信”时，区分论文正文报告的实验/证明与实际完成的原始数据核验或独立复现；附录、数据或复现材料未取得或尚未核验时，仅陈述已读论文报告的证据，不声称已独立验证
- 用户要判断证据强弱或结论是否成立时，核对实际可得的方法、对照、指标、数据、证明或复现记录，逐项说明能支持的范围和缺口；关键依据未取得时标为“证据强度未评估”，不把已读作者结论当作独立裁定。声称复算或复现须有实际输入、步骤和结果
- 涉及比较时，读到选择标准、基线和评价指标后再讨论是否公平、是否切题；材料未取得时明确标为未核验

### 6. 局限与适用边界

- 已读原文中作者承认的局限 + 有证据支持的其他适用边界；未读到局限章节时不代作者下结论
- 说明什么条件下不宜沿用方法、比较框架或推广结论

### 7. 术语表与按需自测

- 对新术语给回查解释。普通练习可给少量边界或前提的问题及答案/判据，不问公式复述；用户要检验理解时先只出题、等作答，再逐题判断、指出误解并针对性纠正，未作答不称检验完成

## 论文场景专属规则

| 规则 | 说明 |
|------|------|
| 公式必须落地 | 每个公式给出"它在做什么"的白话，而不是符号重排 |
| 区分作者主张与事实 | "作者声称 X；实验只支持了 Y"要说清 |
| 不给二手印象 | 具体论文的结论以已读原文为界；只能读摘要时只做摘要层说明，不能评价未读的实验、局限或基线 |
| 图要重画 | 直接搬论文图常常可读性差，按讲解需要用 SVG/mermaid 重画 |
| 可选加"与相关工作关系" | 仅当用户要定位这篇在领域里的位置时才展开 |
