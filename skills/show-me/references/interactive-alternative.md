# 独立交互图的替代路径验收

当请求是 Archify 五类之外的独立交互图型，或 Archify 因环境无法运行、其 Git `origin` + 固定 commit 证据契约无法证明用户要看的源码字节（非 Git 工程、无可用 `origin`/commit、需展示未提交工作区改动）时，可走本路径。Archify 的内容或可读性门槛失败且按诊断修复仍无法通过时，也可另用工具**从头制作新文件**，按本路径完整重新验收；保留原失败诊断，逐项记录涉及的节点/关系、原指标或几何测量及新文件的对应测量结果，并目视核对遮挡、标签或关系问题确已消除。原指标在新文件仍有可比意义时，维持原通过线或更严格；若实现差异使它无法直接移植，说明原因，事先写出替代的可观察通过条件，并提供真实浏览器的几何/样式测量及目视证据。无法据这些证据判断原失败已消除时只交草稿；原失败现象仍存在就不称等效。不沿用失败收据或降低质量门槛。

**可选 Archify 渲染器**：若只因 Git 来源收据无法证明实际非 Git/未提交源码，而 Archify 的布局和浏览器命令可运行，五类受支持图仍可用其 schema、`finalize`、交互 smoke 与视觉检查来生成最终 HTML；这是本替代路径中的一种制图工具，不是 Archify 仓库来源核验。候选同时省略 `meta.repository` 与节点 `sources`，在外部独立记录实际来源，不传 `--repo-root` 冒充来源；Archify 收据只证明候选、HTML 和实际运行的自动检查，`--require-provenance` 只证明 HTML 交付身份。源码字节/行号、必要跨文件同状态与语义对照全部按下面第 1–3 项独立核验，最终文件的交互、目视、可取得副本按第 4–6 项验收，缺项只交草稿；没有 SRC 来源载荷要在交付中说明。Archify 内容/布局门槛若失败仍须修复，不可沿用失败 HTML 降档。其他图型或渲染器不可运行时才用通用 HTML/SVG 等工具，仍走同一替代验收。

**制作前能力检查**：先确认当前宿主能写入最终本地文件，且有用户可取得最终 HTML 的共享工作区、附件或下载通道；能在真实浏览器打开该 `file://` 文件或最终本地 artifact，且确认打开的就是交付对象；能实际设置并检查 1440×900、1600×1000、1920×1080、2048×1320 和用户指定的视口；能对页面实际点击、键盘操作，查看渲染画面并读取运行时错误。通用文件/HTML 编辑与浏览器可满足这些能力，但须逐项确认可执行。缺任一必要能力时，直接定位为草稿并说明缺口，不先制作完再把未验文件称为成品。以下检查针对**最终本地文件**，不要求 Archify 的 schema、命令或专有收据；用普通文字记录实际证据即可。不能把 `HEAD`、虚构的 URL/commit 或 Archify 的 `local-only` 收据当作未提交源码的证明。任一必要项失败或无法核验，就只交草稿并说明缺口。

1. **记录实际依据**：若图反映用户给出的概念或关系约束，记录所据描述及范围；若反映具体代码、论文或系统，按支撑结论的来源逐项记路径或 URL、可取得的版本标识、读取范围和时间。代码图能取得实际读取的完整字节时，记字节数与 SHA-256；只能从在线只读页面或工具取得文本时，保存带可核实行号的受限摘录与读取时间，不补造未读字节的摘要或页面未提供的行号。不同文件的逐次读取不能称为同一时点的原子取证。需长期复现、来源易变且需保留，或为关键跨文件关系建立冻结版本时，才在受限位置保存独立源码快照；只复制所据且可复制的文件，注明覆盖范围，逐文件记录捕获时间、路径、字节数和 SHA-256，并从快照读取或核对它与已取证字节一致。快照是私有取证材料，不默认随图分享；含无关密钥或个人信息时禁止打包外带，必要时改用受限可核验摘录或脱敏副本，并明确其字节不等于原始来源。无法保留必要证据则只交草稿。局部快照不代表整个工程，逐文件复制不声称原子快照。交付前复核仍可访问的来源或快照中支撑关键结论的字节、摘录及行号；若发生变化，更新取证和图后重新检查。关键来源无法稳定复核时，只交草稿并标明未核验部分。Git `HEAD` 只能作背景基线，不能证明未提交字节。
2. **关键跨文件关系的一致性（代码图）**：先列出支撑该关系的全部相关文件及所需行段，确定它们是否必须来自同一源码状态；普通稳定来源和无需同一状态的单文件结论不强制复制。若关系依赖动态目录扫描或插件发现，还须记录发现根、匹配规则和实际匹配路径集合；冻结时将相关目录状态纳入冻结范围，稳定窗口前后核对目录状态和匹配路径集合，不能只哈希已知文件。若必须来自同一状态，记录共同的不可变版本标识并核对它确实对应所读内容；活跃工作区没有这种标识时，任选可核验的路径：（a）用确实能冻结全部相关文件及相关目录状态的机制取得可访问快照，记录冻结机制、范围和版本或时间，从该快照读取并逐文件核对摘要；（b）在确认并记录无并发写入的稳定窗口内（如暂停相关编辑、生成和构建写入），先对全部相关文件取路径、字节数和 SHA-256，再读取所需行段，最后对同一文件集合再次取路径、字节数和 SHA-256，核对两遍清单与摘要完全相同，并记录窗口起止时间。逐文件复制本身不算冻结；双遍哈希也不能排除两遍之间发生又恢复的改动，不能在可能并发写入时宣称原子快照或严格同一时点。文件集合不完整、核对不符或无法证明所需一致性时，重取后重画，仍不能通过就把对应关系标为未核验；若它是完成图的必要关系，只交草稿。

   若动态发现还依赖配置、生成步骤、环境变量或运行时插件注册，按 `workflows/explain-code.md` 的规则把实际影响结果的输入纳入同状态核验；无法复核时只陈述已观察的集合，不称完整运行时发现关系。
3. **来源与关系**：用户描述的概念图以其约束为依据；反映外部具体材料时，记录所依据原文的版本与位置；代码图还须给关键节点、关系和边界可回查的 `文件:行号`，并标明行号对应的已读来源、版本或快照。把用户明确点名的全部节点、关系、条件及其他关键问题列入对照表，逐项记录预期方向/条件、成图位置和证据或未核验状态；再核对参与者、动作、目标、边的起终点与方向，以及影响结论的顺序、条件和归属。缺少用户必需项不得通过语义验收。图与解释一致；没有证据的推断须显式标明，不能画成已证实的事实。
4. **独立文件与身份**：产物是用户可直接离线打开的本地独立文件，所需运行资源内嵌；如保存了源码快照，它作为受限外部取证材料保留，不冒充 HTML 内嵌证明，也不默认随图交付。记下 HTML 的绝对路径、字节数和 SHA-256；在真实浏览器打开该最终文件，并确认检查后 HTML 及已保存的快照摘要未变。交付前确认宿主附件、下载或共享工作区等实际方式，并核对用户可取得的最终副本字节数和 SHA-256 与已验证副本一致；远程容器的代理浏览器能打开本地路径，不代表用户能取得该文件。无法确认可取得且一致时，只交草稿并说明缺口。任何内容修改后，重新打开修改后的最终文件、重复第 4–6 项，并复核受影响的来源与关系。
5. **视口与可读性**：先查看最终 HTML 中影响布局的 CSS/媒体查询与脚本条件，在浏览器确认不同布局及断点附近的表现；四个固定尺寸不自动涵盖中间断点。在真实浏览器检查 1440×900、1600×1000、1920×1080、2048×1320，以及用户指定的视口和其他实际布局的代表尺寸。完整图和控件可到达；无页面水平溢出、裁切、遮盖、含糊箭头、隐藏关系或不可读文字。内容较高可用页面纵向滚动，但须实际滚动检查首屏外卡片和图内容；不能靠隐藏溢出、内部小滚动区或缩小文字掩盖问题。对手工替代图，目视最终渲染；四个默认桌面视口若可证明属于同一渲染布局，可按布局类别抽样并记录依据、实际目视与未逐一目视的视口。用户指定的每个视口必须单独目视，不参与抽样豁免。关系密集或走线、层级有疑点时，另目视相应视口和局部。DOM 溢出测量只可辅助发现越界，不能单独证明无遮挡、箭头清楚或文字可读。
6. **真实交互**：对同一最终文件亲自操作基本浏览和图语义交互：能定位节点及其相连关系、浏览全图并返回全图；节点或关系的选中、聚焦或详情反馈须可见且正确。对第 5 项识别的每种实际布局及用户指定的每个视口，在打开详情或聚焦状态下重复关键节点/关系操作，检查反馈和返回全图控件仍可见、可操作；不能用未激活时的静态视口检查替代。若经用户目标或来源核对确认全图应零关系，记录依据，核对确实零边，并操作节点详情、可见空关系态及返回全图；未证实的零边不算完成。用户指定的搜索、导出、深链等功能逐项操作并核对结果；检查运行时错误。只有静态图、表面按钮，或未经这些检查的手写 HTML，均不能作为完成品。

交付时给用户可取得的 HTML 位置、字节数及 SHA-256、实际读取的来源与范围、关系核对及所需跨文件一致性检查结果、实际测试和目视的视口、交互结果，以及未通过的项目；若保存快照，只说明可披露的覆盖范围和核验结果，除非确有交付必要且可安全分享，不提供快照或其路径。浏览器运行、截图和人工视觉判断分别表述，不相互代替。
