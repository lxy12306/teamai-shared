# Codex、Qoder、Pi 路由与发现

当一套技能需要同时供多个宿主发现，或总 skill 路由到独立子 skill 时读取。共同结构、来源核对和发布规则适用于目标宿主；下表的目录及显式调用方式只针对 Codex、Qoder、Pi。宿主版本和部署配置会改变发现位置，交付前以实际技能列表为准。

## 共同源结构

```text
skills/
  suite/SKILL.md
  suite-a/SKILL.md
  suite-b/SKILL.md
```

每个目录是一项独立 skill，`name` 与目录名一致；所有子 skill 均以父 skill 的完整名称加连字符开头，例如 `suite-a`、`suite-b`，并有自己的 `description` 和完整流程。总入口的描述概括整个套件及各子任务场景，以便在子 skill 缺失时可能成为入口；子 skill 的描述标明更具体的直接触发场景，二者不要完全重复。路由表记录任务信号、职责与预期结果、准确名称、预期的套件或项目来源和交付时状态；状态只是快照，调用时按实际发现信息重查。准备发布的套件在路由表和每个子 skill 正文记录共同修订标识，交付前逐个比对。每个子 skill 独立运行，不把总入口或其中的私有资源当作隐式前置依赖。普通 `references/*.md` 只属于其所在 skill，不会作为独立 skill 注册。

安装前盘点目标宿主默认与自定义技能扫描根中的同名总入口和子 skill，核对预期源文件与目标副本的内容或散列；无法穷尽发现范围时说明限制。先确认副本归属和已知调用者，只修改自己有权处理的副本。新套件遇到不可处理的第三方重名项时，若名称可调整，先给己方总入口选唯一名称，并同步改为对应的 `父名-场景名` 子技能；若用户已固定名称且冲突无法消除，停止该宿主的安装并报告冲突。已发布套件改名还须迁移已知调用者，能保留自有旧名入口时提供兼容，无法保留则说明未知调用者可能中断并将迁移作为破坏性变更。更新路由表后重新盘点。不能靠路由正文解决覆盖；旧版总入口若先被选中，新版的自检根本不会运行。

运行时优先从宿主实际加载信息核对名称、来源、路径和可见的修订，再读取目标 `SKILL.md`；不要把 `../suite-a/SKILL.md` 当成跨宿主固定路径。若技能列表只显示名称，首次或宿主重载、套件更新、来源变化后，从已配置的扫描根找到唯一且名称、来源、修订相符的副本，核对内容后读取；有发布清单时对照目录文件清单及散列，没有清单时与已确认的预期源目录逐文件核对，没有可核对的内容基线则标为未验证，不能仅凭手写修订标识判定内容未变。仅在能确认技能清单与目标文件未变时复用会话内结果，不能判断时重查，不必无条件每次全量扫描。仍无法定位或排除重名时，停止按名称路由并标记为未验证。名称唯一但 Agent 无法读取时，可提供该宿主的显式调用方法；重名时先请有权限的人处理冲突；己方套件可改名时再改名，不把显式调用当成消除重名的办法。每个目标宿主还须确认总入口确能读取子 `SKILL.md` 或用已验证机制调用子 skill；否则只算子 skill 可直调，父路由不可用。可在只装目标版本的隔离宿主中做显式调用测试，但其结果不能证明有重名的实际宿主已安全加载。

| 宿主 | 常见发现位置 | 显式调用总入口 | 安装后的核对 |
|---|---|---|---|
| Codex | 当前文档支持用户或项目的 `.agents/skills/`；旧配置还可能使用 `.codex/skills/` | `$suite` | 查看实际可用技能列表，逐个检查总入口和子 skill；插件打包时各 skill 必须是 `skills/` 的直接子目录。 |
| Qoder IDE/CLI | 用户 `~/.qoder/skills/`；项目 `.qoder/skills/` | `/suite` | 在技能列表中逐个确认；CLI 修改后可重新加载，IDE 可重启后检查。 |
| Pi | 用户 `~/.pi/agent/skills/` 或 `~/.agents/skills/`；项目 `.pi/skills/` 或 `.agents/skills/` | `/skill:suite` | 查看启动发现结果，并用 `/skill:<name>` 逐个确认；编辑后重新加载。 |

同名解析不能只看名称或假定统一优先级：Codex 可能并列显示，Qoder IDE 与 CLI 文档给出的覆盖顺序不同，Pi 会保留先发现的项目；以当前宿主实际加载的来源为准。表中的 `suite` 是示例，实际使用总入口的 `name`。无法列出全部可发现位置或无法确定实际加载来源时，报告该限制，不声称已通过宿主验收。

不要假设一个宿主的用户目录会被另外两个自动扫描。使用 TeamAI 等分发工具时，把总入口和每个子 skill 都列为独立资源，再核对它们在指定宿主中的实际副本；不能只推送总入口。本机核对的 TeamAI 0.27 将 `push --skill` 当作单项技能推送；需要整套待审时，一次 `teamai push` 选中父及所有子 skill，核对待审变更只涉及预期清单且包含全部目录。已有待审资源可能被分到不同变更，不能假定多次 `push --skill --branch` 自动组成一个待审变更；交付时仍以当前 CLI 的资源列表和实际变更为准。把子 `SKILL.md` 嵌在总入口内可能在 Pi 中产生同名重复。若使用角色或项目命名空间，确认整套 skill 都会派送到目标宿主。若目标宿主尚未安装或未启用，只能完成文件结构与静态校验，不能声称已验证该宿主的自动发现。

## 整套发布与回退

1. 首次安装记录目标位置的原始状态及撤销新增文件的路径；更新时保存旧版整套 skill 目录（包括 `SKILL.md`、`references/`、`scripts/`、`assets/` 等实际资源）、宿主附属配置和各目标位置的实际副本。记录与旧行为相关的外部工具或服务版本及其可恢复性；无法恢复时不声称旧行为能回退。列出本次所有 skill 名称、共同修订标识、每个目录内全部文件的内容清单与散列及目标宿主；目录较多时用脚本生成和比对，未改文件可沿用已核对的旧清单，避免手抄。检查名称冲突、已知调用者、已有待审变更，并验证出现部分派送时能否禁用或撤回父入口、恢复旧套件或撤销首次安装，记录处置生效延迟；没有可执行的处置通道时停止发布。确认任务是否要求连续可用；若要求而分发既不能原子切换也不能让兼容的新旧名称并存，先解决交付条件。能一次提交整套待审变更时核对变更清单，但一个变更并不保证各客户端或宿主的派送是原子的。
2. 旧父入口若没有修订核对，不能依赖“先更新子、后更新父”来避免混用。新子与旧父不兼容时，保留旧子，先以另一合规名称交付新子（例如父 `suite` 的 `suite-a-v2`），再切换父路由；父也改名时，新父及其 `新父名-场景名` 子技能与旧套件并存，直至已知调用者迁移。并存期分别测试明确调用目标版本及自然请求的自动选用；自动选用不稳定时只把明确调用列为已验证路径，若错误自动选用不可接受且宿主无法限制，则不用并存方案。若名称必须原位替换且分发不支持原子切换，明确过渡期可能不可用，不声称旧父入口一定能自行停止。
3. 合并或安装后，触发宿主支持的重载或重启，在每个可操作的目标宿主核对全套名称、来源、修订和实际加载副本，再按下节范围运行父路由及子 skill 直调；无法确认加载版本时标为未验证。只派送一部分时暂停继续派送，通过预检通道禁用或撤回不一致的父入口，或恢复整套旧版；无法即时生效时报告暴露窗口及受影响客户端，不声称父路由已停止。尚未生效的待审变更可不发布；首次安装已生效后发现问题时撤销新增文件并恢复目标原状态，更新已生效后发现问题时从快照恢复**整套**旧版（含资源及宿主附属配置）并重新派送。撤销后确认新技能不再被发现；恢复旧版时按清单核对目标文件，确认各客户端重新加载，并在可操作的宿主复测旧父路由及子 skill 直调。分发工具可能保留本地改过的副本，不假定再次拉取或强制拉取会覆盖它；先确认归属和实际副本。

## 路由测试

仅交付文件时，逐个对总入口与子 skill 运行结构验证器，检查父名前缀、目录、元信息、共同修订标识、路由表、链接和交付清单一致，并记录宿主行为未验证。能在隔离宿主加载套件时，用宽泛请求检查总入口选出一个主子 skill；父与所有子 skill 同时安装时，逐个用窄场景自然请求检查选用和结果，另在仅安装单个子 skill 的隔离环境中检查其可直调；再用跨职责请求检查仅在必要时组合。只在隔离副本中移除子 skill，分别检查**明确调用总入口后**的缺失提示和**自动选用**能否触发总入口；后者无法保证时提供明确调用方法。在同一隔离环境模拟同名不同来源的子 skill，检查能否确认实际加载的来源及修订，测试后恢复隔离副本，不改动正在使用的安装目录。实际安装到任务指定的宿主时，逐个检查发现状态与目标副本；首次安装、父路由规则或发现布局改变时，在每个可操作的宿主对路由表中的每个子 skill 运行父入口路由请求和直接调用，交付要求自动选用时逐个用窄场景自然请求检查，支持组合时另测代表性跨职责请求；只改子流程时复测受影响分支及相邻、组合回归。记录已测分支与组合的选用、读取和结果，未测试项标为未验证；宿主不可操作时只报告已验证到的层次。
