---
name: gen-skill
description: 生成或迭代生产级 SKILL.md 及其目录结构。触发词：生成 skill、新建 skill、创建技能、迭代 skill、拆分 skill、合并 skill
---

## 基础约定

| 变量 | 值 |
|------|-----|
| `{SKILL_DIR}` | `skills/<kebab-case-name>/` |
| `{MAIN}` | `{SKILL_DIR}/SKILL.md` |
| 命名 | 小写 + 连字符，见名知意；禁止 `helper`、`utils`、`misc` |

**输入清单**

| 输入 | 必填 | 缺失处理 |
|------|------|----------|
| skill 用途/场景描述 | 是 | 追问 |
| 目标复杂度（L1-L4） | 否 | Step 1 自动判定 |
| 已有 SKILL.md（迭代场景） | 否 | 视为新建 |

**输出结构（按复杂度裁剪）**

| 层级 | 产出 | 主文件行数上限 |
|------|------|---------------|
| L1 | `{MAIN}` 单文件 | ≤100 行 |
| L2 | `{MAIN}` + 可选 `references/` | ≤200 行 |
| L3 | `{MAIN}` + 场景≥2 时拆 `workflows/` | ≤400 行 |
| L4 | `{MAIN}`(路由层) + `workflows/` + `commons/` + 可选 `references/` + `evolution-log.md` | 路由层≤150 行 |

## 决策规则

### 复杂度判定

| 条件 | 结论 |
|------|------|
| 封装单个脚本/API，输入→输出，无决策，≤5 步 | L1 |
| 有格式规范或策略选择，覆盖单一业务场景 | L2 |
| 多步骤 + 条件分支 + 人机交互 | L3 |
| L3 + 多场景共存 + 严格校验机制 | L4 |

### 是否引入分层架构

| 条件 | 处理 |
|------|------|
| 场景 = 1 且主文件 ≤ 400 行 | 单文件 |
| 场景 ≥ 2 或主文件 > 400 行且仍增长 | 拆为路由层 + `workflows/` |

### 必须追问的情况

| 情况 | 原因 |
|------|------|
| 无法判断单一职责边界 | 可能需拆多个 skill |
| 与已有 skill 功能重叠 | 需确认扩展还是新建 |
| 用户描述含多个互斥场景 | 影响复杂度定级 |

其余情况能推断则不追问。

## 工作流

### Step 1: 对齐范围与复杂度定级

- 确认单一职责：一个 skill 解决一类问题
- 扫描仓库 `skills/*` 检查重复（近似则扩展原 skill）
- 按决策规则表判定 L1-L4
- ⚡ **交互点**：仅在"必须追问"条件命中时询问用户
- ❌ **异常**：用户需求模糊到无法定级 → 给出 2-3 个拆分方案供选择

### Step 2: 命名与目录结构

- 确定 `{SKILL_DIR}` 路径
- 按基础约定"输出结构"表创建目录骨架
- ⚡ **交互点**：无（自动完成）
- ❌ **异常**：命名与已有 skill 冲突 → 提示用户重命名或合并

### Step 3: 撰写目标 skill 的 SKILL.md 并引入支柱

**六区段模板**（按级裁剪：L1 只写 ★ 标记项。注释为撰写指引，不写入产出文件）

```markdown
---
name: <kebab-case>
description: <使用场景 + 触发关键词列表>    ★
---

## 基础约定                    <!-- L2+ -->
## 决策规则                    <!-- L3+ -->
## 工作流                      ★
## 质量保证                    <!-- L2+ -->
## 汇报                        ★
## 约束                        <!-- L2+ -->
```

**各区段写作要点**

| 区段 | 写什么 | 怎么写 |
|------|--------|--------|
| 元信息 | name + description（路由依据，含触发词） | frontmatter ≤3 行 |
| 基础约定 | 路径变量、输入/输出清单、术语定义 | 表格；一处定义处处引用 |
| 决策规则 | 条件→动作映射 | 表格；>3 分支用 flowchart |
| 工作流 | 编号步骤；每步标注 ⚡交互点、❌异常路径 | 每步≤5 行 |
| 质量保证 | 校验规则 + 留痕格式 + 失败处理协议 | checklist 式 |
| 汇报 | 完成后输出什么 | L1 一句话；L3/L4 按阶段明细 |
| 约束 | 禁止项、边界、与其他 skill 关系 | bullet list |

**四大支柱引入规则**（撰写时同步判断，按需嵌入对应区段）

| 支柱 | 引入条件 | 跳过条件 | 嵌入位置 |
|------|----------|----------|----------|
| 分层架构 | L3 场景≥2 或 L4 | L1-L2；L3 单场景 | 目录结构 + 工作流区段 |
| 渐进式加载 | L4 | L1-L3 | 工作流区段内加载指令 |
| CLI 委托 | 满足阈值（任何层级） | 数据<10行、单次性、需语义理解 | 工作流对应步骤 |
| 验证闭环 | L2+ | L1 仅结构自检 | 质量保证区段 |

分层架构要点：
- SKILL.md 做路由（声明式路由表 + 公共约定），`workflows/` 每场景一个文件
- 路由表含状态列（✅可用/🚧开发中/❌不支持），LLM 遇到非 ✅ 状态直接告知用户不支持
- 新增场景 = 加一行 + 新 workflow，不动已有文件
- `commons/` 入选标准：≥2 workflow 引用
- **主体自包含**：每个 workflow 不依赖外部文件即可理解主流程

渐进式加载要点：
- 每个加载点写明三要素：加载条件 / 加载文件 / 跳过条件
- 拆分粒度：每次都用+<30行→留主文件；条件触发→拆出去；纯参考类→一定拆

CLI 委托阈值：目标 skill 处理的业务数据>3000行或List>10元素 / 同一操作N>5次 / 数值计算正则ID关联 / XML/JSON解析编码转换。LLM做语义决策交互，脚本做确定性计算。

验证闭环深度：L1结构 / L2结构+数据 / L3结构+数据+一致性 / L4全部+编译。

- ⚡ **交互点**：L3+ 生成完成后展示给用户确认再落盘；L1-L2 直接落盘
- ❌ **异常**：内容超出层级行数上限 → 迁入 `references/` 或拆 `workflows/`；支柱不适用 → 在约束中注明原因并跳过

### Step 4: 自检

1. 对已写入的文件执行质量保证章节中对应层级的自检清单
2. 自检失败 → 修复失败项 → 仅对失败项重新自检（最多 3 轮，仍失败则标注待修复项报告用户）
3. L4：创建/追加 `{SKILL_DIR}/evolution-log.md`（倒序时间线，每条：动机→变更→影响→教训）

- ⚡ **交互点**：自检发现必修项（元信息缺触发词、工作流有歧义步骤）时，修复后再次展示用户确认
- 🔄 **中断恢复**：通过已写入文件判断进度，从下一未完成步骤续接

### Step 5: 迭代维护（已有 skill 改版时执行）

1. **先读取**已有 `{MAIN}` 及相关文件，理解当前结构
2. 按症状表定位改动范围：

| 症状 | 优先改哪里 |
|------|------------|
| 常被误用或漏用 | 元信息 description + 触发词 |
| 会做但做错 | 工作流步骤 + 决策规则 |
| 能做但不安全 | 约束 |
| 正文过长难维护 | 拆入 `references/` 或 `workflows/` |
| 场景膨胀 | 引入分层架构 |
| 需拆分为多个 skill | 新建各子 skill(走 Step 1-4) → 原 skill 缩减或删除 → 更新所有相关 skill 的元信息与约束 |
| 需合并多个 skill | 选定保留 skill → 合入其他 skill 内容 → 删除被合并 skill → 更新相关引用 |

3. 小步修改，一次解决一类问题
4. 改完跳转 Step 4 重跑自检
5. L4 或有 `evolution-log.md` 的目标 skill：追加进化日志条目

- ⚡ **交互点**：涉及结构性变更（如从单文件升级为分层）时确认用户意图
- ❌ **异常**：已有 skill 结构混乱无法增量改 → 建议用户全量重写并说明原因

## 质量保证

### 通用自检（所有层级）

- [ ] 元信息 description 含触发关键词，可独立判断是否该用本 skill
- [ ] 工作流可逐步执行，无「视情况而定」却不给默认做法
- [ ] 全文术语统一（同一概念不混用多种叫法）
- [ ] 主文件只写 Agent 不知道的，常识不赘述
- [ ] 主文件未超出对应层级行数上限

### L2+ 追加

- [ ] 基础约定完整（输入清单标注必填/缺失处理）
- [ ] 条件判断全用表格，无散文描述边界

### L3+ 追加

- [ ] 决策规则表格化，条件→结论无歧义
- [ ] 工作流每步标注 ⚡交互点 和 ❌异常路径
- [ ] 质量保证区段有具体验证手段和失败处理

### L4 追加

- [ ] 路由表声明式，新增场景不动已有 workflow
- [ ] 各 workflow 主体自包含（不依赖外部文件即可理解主流程）
- [ ] 渐进加载指令含三要素（加载条件/加载文件/跳过条件）
- [ ] `evolution-log.md` 存在且首条有内容

### 校验留痕格式

```
【自检】(层级: L<N>, 时间: yyyy-MM-dd)
- 元信息: ✅/❌ <具体问题>
- 基础约定: ✅/❌ / N/A
- 决策规则: ✅/❌ / N/A
- 工作流: ✅/❌ <具体问题>
- 质量保证: ✅/❌ / N/A
- 约束: ✅/❌ / N/A
- 行数: <实际> / <上限> ✅/❌
- 结论: 通过 / 需修复 [<问题列表>]
```

## 汇报

**L1-L2：**
```
✅ 已生成 `{SKILL_DIR}/SKILL.md`（L<N>）
- 辅助文件: <列表或"无">
```

**L3-L4：**
```
✅ 已生成 `{SKILL_DIR}/SKILL.md`（L<N>）
- 区段: <已写区段列表>
- 目录结构: <产物树>
- 辅助文件: <列表或"无">
- 自检结论: 通过 / 待修复 [<列表>]
- 下一步建议: <可选>
```

## 约束

- 默认写入当前仓库 `skills/`；用户指定路径则遵从
- 主文件行数上限按层级：L1≤100、L2≤200、L3≤400、L4路由层≤150
- 不假设特定 IDE/产品名，除非用户明确绑定
- 不过度设计：L1 不引入分层架构和验证闭环；L2 不引入渐进加载
- 兼容性：已有五段式 skill（Description/Purpose/When/How/Constraints）可保持原格式迭代；新建 skill 统一用六区段
- 反模式：整篇教程式背景、无触发条件的 description、与 description 矛盾的工作流
- 迭代时不「只堆字数」：优先改触发条件、步骤与约束
- 合并/拆分 skill 后必须更新相关 skill 的元信息与约束，避免调用冲突
- **写作规范**（撰写目标 skill 全文时贯穿执行）：表格优先（条件/参数/IO 全用表格）、消除过渡句、层级内聚（同概念一处定义）、路径用变量、边界表格化
