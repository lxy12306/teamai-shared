# 工单格式

沿用项目现有工单格式与目录；默认落 `docs/tickets/NNNN-<slug>.md`，序号扫描目录取最大 +1。每张工单应有可独立验收的交付价值；允许显式依赖前序工单。

## 模板

```md
# NNNN · <工单标题>

> 来源：<spec 路径及 R 编号，或已确认需求/共识的具体条目>   ·   依赖：<前置工单编号或「无」>

## 目标
{这张工单交付的最薄端到端价值，一句话。}

## 范围
- 做：<本单穿透的完整链路>
- 不做：<刻意留给其他单的>

## 验收标准
- [ ] Given <前提> When <动作> Then <结果>
- [ ] <其他可验收判据>

## 备注
<实现提示、风险、需协调的点（可选）>
```

## 规则

| 检查 | 要求 |
|------|------|
| 端到端 | 优先切完整用户行为；有独立验收价值的基础设施或迁移任务可单列 |
| 可独立交付 | 前置工单完成后，本单可单独实施和验收；可以依赖尚未完成但已明确排序的前序单，不得形成环 |
| 可验收 | 验收标准明确，能判定「做完了」 |
| 可追溯 | 引用 spec 的 R 编号；无 spec 时引用已确认需求或共识的具体条目，不伪造来源 |
| 小步 | 一张 = 一次可评审交付；过大再拆 |

第一张工单尽量打通最薄主链路，后续工单可以加厚或并行扩展；整组工单须覆盖本次已确认需求，并检查孤儿工单与依赖环。
