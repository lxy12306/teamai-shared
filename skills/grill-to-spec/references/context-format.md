# 术语文件格式

先沿用目标项目已有的 `GLOSSARY.md`、`CONTEXT.md`、`CONTEXT-MAP.md` 或等价术语文档；默认在根目录新建 `CONTEXT.md` 的 `## Language` 章节。不要因格式不同而创建第二套相互冲突的定义。多业务上下文且项目已有 context map 时，按映射更新对应上下文的文件。

```md
## Language

**Order**：客户提交并由系统跟踪的购买意向。
_Avoid_: Purchase（只有团队实际混用时才列）

**Invoice**：交付后向客户发出的付款请求。
```

- 每条只写本领域需要统一的规范名称和一两句定义；通用编程词不收。别把函数、表结构或实现步骤写进术语定义。
- 仅在存在真实混用或旧称时写 `_Avoid_` / 别名及原因；目标设计改名时记录“当前称呼 → 目标称呼”，不要把旧名当成永远禁止的词。
- 定义冲突时保留原文并请用户裁定；未确认的新定义在提案或 draft 中，不直接改权威术语文件。
- 多上下文时用项目现有映射；若确需新建 `CONTEXT-MAP.md`，列上下文、文件位置和它们实际已确认的关系，不凭目录猜测。无自然边界时保持一个术语文件即可。
