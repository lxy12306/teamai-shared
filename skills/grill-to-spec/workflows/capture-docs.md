# S2 · capture-docs（术语、领域模型与 ADR）

按用户实际要求沉淀术语、领域关系或设计取舍；三种产物可单独生成。来源可以是已确认的 S1 决策、用户给出的明确结论、已有 spec 或可核验的项目文档。没有共识文件时不强制重跑 S1；影响模型或决策的关键未知才澄清。

## 目标位置

先确认当前目录就是目标项目或用户指定的文档位置。访谈在临时分支、草稿工作树或独立会话中进行时，不把未来设计直接写入当前实现的术语表或 ADR；先给出文件就绪的提案，待目标位置明确再落盘。已有项目约定优先于默认目录，增量编辑并保留无关内容。

## 术语

读取项目已有的 `GLOSSARY.md`、`CONTEXT.md`、`CONTEXT-MAP.md` 或等价文件，确定唯一权威入口；两个文件并存且定义冲突时，指出冲突并请用户裁定。只收本领域需要统一的概念：规范名称、简短定义、必要的反例或避免用法。用户给出的目标用词与现有代码用词不同可记录迁移关系，不把现状当作禁止变更的约束。格式见 [术语格式](../references/context-format.md)。

## 领域模型

用户要求 `domain model`、实体关系或领域不变量时，读 [领域模型格式](../references/domain-model-format.md)，写 `{DOMAIN}` 或项目既有位置。模型描述业务概念、身份和值、关系、基数、生命周期及不变量；只收本次范围需要的部分，不凭类名或表名臆造业务规则。把已观察到的当前模型与拟议的目标模型分开，未确认的关系留在 `draft`；无需同时新建术语表或 ADR。

## ADR

对会长期影响架构、外部契约或团队协作且理由不易从代码看出的真实取舍，考虑 ADR；可逆、显然或没有备选的细节通常不需要。用户明确要求 ADR 或项目已有更具体约定时按其目标处理。编号沿用项目规则，默认扫描 `{ADR_DIR}` 中现有 `NNNN-*.md` 取最大序号加一；遇到并发冲突重查，不覆盖已有文件。只有有权裁定者已确认决定并有可回查依据时才标 `accepted`，未来方案先标 `proposed`。格式见 [ADR 格式](../references/adr-format.md)。

## 自检与交接

- 术语、模型与 ADR 的同名概念一致，来源可回查；未来设计未被写成当前事实。
- 模型关系和不变量有场景或证据；ADR 说明所选方案、重要备选与取舍，不为填模板虚构选项。
- 本次请求的产物已写入正确位置，或明确给出待应用提案及阻碍。若用户还要求 spec，继续 S3，不在已授权阶段之间停下征求许可。
