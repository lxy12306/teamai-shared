# S1 · grill（压实决策）

围绕用户要完成的本次目标压力测试方案。先读方案及相关项目事实，再追问真正会改变交付结果的选择；不为“每个方面都问过”而无限访谈。明确要求深入拷问时覆盖所有本次范围内的重大分支。

## 决策树

1. 锚定目标、范围、使用者和验收结果。已在输入中说清的内容不重复问。
2. 找出候选分支，只把可能改变行为、边界、数据/权限、接口、运维风险、迁移或验收的未知项放入待决树。按依赖排队，上游未定时不抢问下游。
3. 对每个已解锁分支，先查代码、文档和现有契约；事实不交用户猜。区分“当前行为是什么”与“目标行为要变成什么”，两者不同不构成冲突；必要时追问迁移、兼容与回滚。
4. 默认一次问一个最影响本次结果的问题，附可选方案、代价和基于本项目证据的推荐。没有支撑本次选择的项目事实或用户偏好时，只给选项与取舍并请用户裁定；不写“倾向”“默认建议”或等价的优先暗示，通用产品直觉不算本项目证据。用户要求加快时可把互不依赖的问题合成一轮；仍等答复后再打开依赖分支。
5. 用一个具体的正常或失败场景检验含糊回答。用户答案改变先前结论时，重开受影响分支，并标出要回修的 spec、术语、ADR、工单或计划。

每个分支标记其处置：`confirmed`（用户或经确认有权裁定的负责人明确裁定）、`resolved-by-evidence`（事实或适用的有效契约已查证）、`out-of-scope`（明确排除且有后果）、`accepted-risk`（有权主体明确承担剩余后果，记承担者与依据）或 `open`。无人明确承担的风险不能以 `accepted-risk` 关闭；若本次范围仍依赖它，就保持阻塞。低影响、可逆的实现细节可作为注明依据的假设，不必向用户逐项请示。

记录决策或事实时，来源须指向可回查证据：有会话链接或消息定位时记定位和必要的脱敏短引文；没有时记答复日期、主题及必要的脱敏短引文，并标明无法跨会话精确定位。文件记路径、章节或行号及版本；契约记名称、生效版本与条款。不能编造消息 ID，也不能只写“用户答复”或“现有文档”。

## 停止与交接

当本次范围内会改变目标、行为和验收的分支均已关闭，剩余未知已明确为不阻塞的假设、风险或范围外，且至少一个代表性场景能解释清楚时，给出简短共识与剩余风险。用户只要 S1 时在对话中交付并收尾；用户同时要求后续产物时继续执行已授权阶段。

需要跨会话交接或用户要求保存时，按已确认的目标项目写 `{CONSENSUS}`；处于临时或非目标工作树时先在对话中保留文件就绪草稿。共识至少包含：目标与范围；带稳定 ID 的决策、状态、理由和确认来源；带路径/版本的已查证事实；当前行为与目标行为；开放问题及其阻塞范围。`confirmed` 只用于有权裁定者实际确认的选择；契约直接约束的事项标 `resolved-by-evidence` 并核实其适用范围，草稿文件存在不代表确认。
